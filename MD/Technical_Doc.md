# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ И АРХИТЕКТУРА СКРИПТА АВТОМАТИЗАЦИИ (v2.0)

**Язык разработки:** AutoHotkey v2.0
**Среда выполнения:** OS Windows 10/11
**Архитектура:** Event-Driven (событийно-ориентированная) с глобальным состоянием (State Machine).

---

## 1. БАЗОВАЯ КОНФИГУРАЦИЯ И СТРУКТУРА ДАННЫХ

### 1.1. Директивы инициализации
- `#Requires AutoHotkey v2.0`: Принудительный запуск скрипта через интерпретатор AHK версии 2.0 (синтаксис строго типизирован, используются функции и объекты вместо устаревших команд v1).
- `#SingleInstance Force`: Предотвращает запуск дубликатов скрипта. При повторном запуске старый процесс принудительно завершается, и в оперативной памяти остается только актуальная версия.

### 1.2. Персистентное хранилище (settings.ini)
Скрипт сохраняет свои состояния в локальный файл `settings.ini`, который создается в директории скрипта (`A_ScriptDir`).
**Структура INI-файла:**
*   Секция `[Stats]`:
    *   Ключ `ComboMax`: Хранит абсолютный рекорд успешных звонков подряд (Integer).
*   Секция `[DailySales]`:
    *   Ключ `yyyy-MM-dd` (динамический): Хранит количество продаж (Integer) за конкретную дату.

### 1.3. Глобальные переменные (Global State)
- `todayKey` (String): Текущая дата (`FormatTime(A_Now, "yyyy-MM-dd")`). Используется для сброса счетчика продаж в полночь.
- `todaySales` (Integer): Счетчик продаж за текущие сутки.
- `comboCurrent` (Integer): Текущая серия дозвонов. Обнуляется при недозвоне.
- `currentMode` (Integer): Состояние стейт-машины. Возможные значения:
  - `0` - Обычный режим клавиатуры (NORMAL)
  - `1` - Режим SIP-клиента (MICROSIP)
  - `2` - Режим CRM (BITRIX)
  - `3` - Режим Сверки (SVERKA)
  - `4` - Режим мессенджера (TELEGRAM)
- `lastWorkMode` (Integer): Буфер для возврата к предыдущему рабочему режиму.
- `callCount` (Integer): Счетчик количества вызовов на один и тот же `currentPhoneNum`.

## 2. ГРАФИЧЕСКИЙ ИНТЕРФЕЙС (GUI) И ВИДЖЕТЫ

Модуль отвечает за отрисовку плавающих окон (Оверлей) поверх окна программы MicroSIP. 

### 2.1. Характеристики окон
Используются опции: `+AlwaysOnTop` (поверх всех окон), `-Caption` (без заголовка и рамок), `+ToolWindow` (не отображается на панели задач), `+Owner` (привязка к потоку). Шрифты: `Segoe UI`.

### 2.2. Трекинг окна (Асинхронный таймер)
- Функция `AttachWidgetsToMicroSip()` вызывается каждые 100 мс через `SetTimer`.
- **Логика отслеживания:**
  1. Проверяет `todayKey`. При смене суток подтягивает/обнуляет данные из INI.
  2. Ищет дескриптор `hwnd` процесса `ahk_exe microsip.exe`.
  3. Проверяет состояние окна `WinGetMinMax(hwnd)`. Если окно свернуто (`-1`) — вызывает метод `.Hide()` для всех трех виджетов.
  4. Получает координаты и размеры окна `WinGetPos(&X, &Y, &W, &H)`.
  5. Если `W == 0` или `H == 0` (фантомное окно в системном трее) — скрывает виджеты.
  6. Высчитывает смещения (Offsets) относительно левого верхнего угла `(X, Y)` и проецирует виджеты с параметром `NoActivate`, чтобы не красть фокус ввода у основной программы.

## 3. ЯДРО ВАЛИДАЦИИ И ПАРСИНГА ДАННЫХ

### 3.1. `FormatPhoneNumber(num, add998)`
Низкоуровневая функция очистки строк от мусорных символов.
- **Действие 1:** `RegExReplace(num, "\D", "")` — регулярное выражение, удаляющее всё, кроме цифр `[0-9]`.
- **Действие 2:** Валидация длины (`StrLen`). Допускаются длины от 9 до 12 символов. Иначе — возврат `"Error"`.
- **Действие 3:** Если длина 10 или 11 символов, берется срез `SubStr(cleanNum, -9)` (последние 9 цифр).
- **Действие 4:** В зависимости от булевого флага `add998`, возвращает либо 12-значный номер (с префиксом `998`), либо чистый 9-значный номер.

### 3.2. `GetValidPhoneNumber(add998)`
Автоматизированный парсер табличных данных (Excel / Google Sheets) с системой отказоустойчивости.
- Цикл `Loop 15` итерирует до 15 строк вниз.
- На каждом шаге эмулируется `Ctrl+C` и ожидается заполнение буфера `ClipWait(0.6)`.
- Если буфер пуст или ячейка пустая, счетчик `emptyCount` увеличивается. 
- При достижении `emptyCount >= 2` (две пустые ячейки подряд), функция понимает, что список завершен, выводит `ToolTip` и прерывает цикл.
- Если считан текст, вызывается `FormatPhoneNumber`. 
- **Обработка исключений:** Если номер битый (например, текст вместо телефона), скрипт сдвигается на 2 ячейки вправо `Send("{Right}{Right}")`, записывает туда слово `"Error"`, возвращается влево и переходит на строку ниже.

## 4. БИЗНЕС-ЛОГИКА: АВТОМАТИЗАЦИЯ ВЫЗОВОВ

### 4.1. `ProcessSipCall(statusText)`
Используется в режимах `MicroSIP` и `Bitrix`.
- Инициирует `RegisterCombo(statusText)`.
- Сбрасывает текущий звонок `{Enter}`.
- Переключается на предыдущее окно (таблицу) через `!{Tab}`.
- Смещается на **две** ячейки вправо, вставляет `statusText`, нажимает `{Enter}` (сохранение ячейки), возвращается `Up`, `Left`, `Left` и смещается `Down`.
- Запускает `GetValidPhoneNumber(false)` для поиска следующего валидного номера.
- При успехе переключается обратно в MicroSIP `!{Tab}` и вставляет номер с инициацией вызова `^a^v{Enter}`.

### 4.2. `ProcessSverkaCall(statusText)`
Полный аналог `ProcessSipCall`, но адаптирован под геометрию таблицы Сверки: сдвиг для вставки статуса происходит на **одну** ячейку вправо, а не на две.

## 5. КОНТРОЛЛЕРЫ РЕЖИМОВ (Стейт-машина)

Глобальный стейт управляется F-кнопками, которые переопределяют поведение всего скрипта.

- **`$F10` (Конфигуратор):** Генерирует GUI для изменения текстовых значений переменных `statusF2`, `statusF3`, `statusF4` (для обычных режимов) и `statusSverkaF2`, `statusSverkaF4`. Кнопка "Сохранить" обновляет переменные и уничтожает окно.
- **`$F11` (Главный переключатель):** Меняет значение `currentMode` по циклу: `2 (BITRIX)` -> `3 (SVERKA)` -> `0 (NORMAL)` -> `2...`
- **`$F12` (Вторичный переключатель):** Тогл между `1 (MICROSIP)` и `4 (TELEGRAM)`.

## 6. МАРШРУТИЗАЦИЯ ФУНКЦИОНАЛЬНЫХ КЛАВИШ

Используется блокировка рекурсии (`$`) для предотвращения зацикливания виртуальных нажатий. Каждая кнопка содержит конструкцию `if/else if`, распределяющую логику в зависимости от `currentMode`.

### Клавиши взаимодействия
- **`$F1`**: Повторный набор номера в SIP. В режиме TG (4) переходит в таблицу и забирает новый номер.
- **`$F2`**: Позитивный сценарий (`boradi`). В режиме 2 (Bitrix) копирует номер, форматирует (true), переключается в Telegram, очищает поиск (3 раза `Escape`), переходит в глобальный поиск (`Ctrl+K`) и вставляет номер.
- **`$F3`**: Сценарий отказа (`ko'tarmadi`). В TG удаляет 998, в таблицах ставит статус и забирает следующий номер.
- **`$F4`**: Промежуточный сценарий (`gaplashilingan` / `ko'chada`). В Bitrix (2) переносит номер из поиска Telegram обратно в MicroSIP и звонит.
- **`$F6`**: Жесткое завершение процесса `microsip.exe` через команду `WinClose`.
- **`$F7`, `$F8`, `$F9`**: Дополнительные макросы умного копирования и вставки, интегрированные с регулярными выражениями. Переносят номера между буфером обмена и мессенджерами.

## 7. СИСТЕМНЫЕ МАКРОСЫ И УПРАВЛЕНИЕ ОС

### 7.1. Дашборд и Статистика (`PrintScreen` / `Insert`)
- **`$PrintScreen`:** Вызывает панель задач Windows `Win+1` (гарантированная активация MicroSIP), завершает вызов. Увеличивает `todaySales` на `1`, сохраняет в INI-файл с ключом текущей даты.
- **`$Insert`:** Считывает массив строк из `salesData`. Использует цикл `Loop` для генерации до 10 полосок Progress-баров (`chartGui.Add("Progress")`). Высчитывает максимальное значение продаж за 10 дней (`maxVal`) и пропорционально строит ширину полосок графика с шагом в пикселях.

### 7.2. Развертывание рабочих пространств (`Pause`)
Функция полной автоматизации запуска софта и раскидывания его по виртуальным рабочим столам Windows (Virtual Desktops).
- **Hard-reset позиции:** `Loop 8 { Send("^#{Left}") }` - сброс фокуса на крайний левый стол.
- **Раскладка:**
  - *Стол 1:* Sublime Text.
  - *Стол 2:* YouTube (в Chrome) + Яндекс Браузер.
  - *Стол 4:* Chrome (Склад CRM) + Калькулятор (прибивается в правую часть экрана `Win+Right`).
  - *Стол 5:* Две Excel-таблицы (Размеры и Локации).
  - *Стол 3:* Bitrix24 + Telegram Desktop + MicroSIP (остается активным).
- **Синхронизация:** Каждое действие сопровождается `Sleep(1500)` для предотвращения гонки потоков (Race Condition) операционной системы.

### 7.3. Kill-Switch (`ScrollLock`)
Аварийное прерывание.
- Отправка `{Shift up}{Ctrl up}` для сброса залипших модификаторов клавиатуры.
- Итерация по массиву `killList` (11 исполняемых файлов). 
- Использование цикла `while ProcessExist(proc)` в связке с `ProcessClose(proc)` гарантирует, что процесс будет принудительно выгружен из памяти.
- Очистка рабочего стола `Win+D`.

### 7.4. Навигация и Медиа-перехваты
- **`$Volume_Down` / `$Volume_Up`:** Переопределены на сдвиг виртуального рабочего стола влево (`Ctrl+Win+Left`) и вправо (`Ctrl+Win+Right`).
- **`$Browser_Home`:** Принудительное закрытие вкладки `Ctrl+W` и моментальный сдвиг влево на соседний рабочий стол.
- **Медиа-плей (`$Launch_Media`, `$Launch_App1/2`)**: Захват буфера обмена, извлечение чистого номера. Очистка контекста Telegram (`Escape x3`), навигация стрелками `Down` во второй закрепленный чат ("Сверка") и отправка подготовленных данных.
